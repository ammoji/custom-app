# PR 45.2 — Fix push token registering to the anonymous user (Windsurf prompt)

## Root cause (confirmed via PR 45.1 diagnostic probes)

The PR 45.1 probes resolved the multi-day push mystery in one
reproduce. Sentry breadcrumb evidence:

```
bootstrap: reached push branch
{
  alreadyRegistered: false,
  isAnonymous: true,        ← registering for the ANONYMOUS user
  uidPrefix: Lb5D6Ske       ← NOT the admin's Nb452wQ...
}
```

…followed by `push: registerPushToken callable RESOLVED` — the
**entire registration chain completed successfully**, but for the
wrong user.

The actual sequence:

1. App launches → `AuthBootstrap` mounts → Firebase signs in an
   **anonymous user first** (`signInAnonymouslyIfNeeded`, uid
   `Lb5D6Ske…`).
2. The push branch fires for that anonymous user.
   `getExpoPushTokenAsync` succeeds, `registerPushToken` callable
   resolves → token written to `users/Lb5D6Ske…/fcmTokens`.
3. The session gate flips: `pushRegisteredOk = true`.
4. The user signs in with the real phone (admin, uid
   `Nb452wQ…`) → auth upgrades.
5. The push branch re-evaluates → `alreadyRegistered: true` →
   **short-circuits**. Never re-registers for the real user.
6. Result: the token sits on the throwaway anonymous user's doc.
   The real account's `fcmTokens` stays empty → no order pushes
   ever delivered.

**This is NOT a build / provisioning / APN issue.** The token
mints fine, the callable resolves — the pipeline works. It's a
pure client-side gate bug: the token registers to the wrong
(anonymous) user and the session-wide boolean gate prevents the
correction. **OTA-fixable. No build 18 needed.**

Why it surfaced on build 17: timing. The anonymous-sign-in →
push-registration → real-sign-in race was latent; build 17's
startup order (post-rebrand bundle) made the anonymous
registration win the race consistently.

## The fix — make the gate UID-aware, in the pure orchestrator

PR 45 already extracted the gate logic into a pure orchestrator
(`src/services/pushRegistrationOrchestrator.ts`) specifically so
this kind of decision is testable without a React mount. PR 45.2
extends that orchestrator with two new rules:

1. **Skip anonymous users.** Push notifications are for order
   updates, which require a real account. Registering a token for
   the throwaway anonymous session is pointless and is the direct
   cause of this bug.
2. **Re-register when the authenticated UID changes.** Track
   *which uid* was last successfully registered, not just a
   boolean. When the user upgrades anonymous→real, or switches
   between real accounts (which happens constantly during
   testing), the token follows the current user.

Keeping all the gate logic in the orchestrator (not in
AuthBootstrap) means the fix is covered by pure unit tests — no
`@testing-library/react-native` needed, consistent with the
PR 45 posture.

## Scope of changes

### A. Orchestrator — new UID-aware signature

`src/services/pushRegistrationOrchestrator.ts`:

```ts
export type RunPushRegistrationInput = {
  /** The authed user's uid, or null if no user. */
  currentUid: string | null;
  /** Skip push registration entirely for anonymous users. */
  isAnonymous: boolean;
  /** The uid we last SUCCESSFULLY registered a token for, or null. */
  lastRegisteredUid: string | null;
  /** The actual registration side-effect (pushService). */
  registerForPush: () => Promise<string | null>;
  logger?: {
    breadcrumb?: (msg: string) => void;
    captureException?: (err: unknown) => void;
  };
};

export type PushRegistrationOutcome =
  | { kind: 'registered'; token: string; uid: string }
  | { kind: 'skipped'; reason: SkipReason }
  | { kind: 'failed'; error: unknown }
  | null; // no user at all

export type SkipReason =
  | 'no_user'
  | 'anonymous'
  | 'already_registered_this_uid'
  | 'null_token';
```

Gate logic (in priority order):

```ts
export async function runPushRegistration(
  input: RunPushRegistrationInput,
): Promise<PushRegistrationOutcome> {
  const { currentUid, isAnonymous, lastRegisteredUid,
          registerForPush, logger } = input;

  // 1. No user → nothing to do.
  if (!currentUid) {
    return null;
  }
  // 2. Anonymous user → skip. Push is for real accounts only.
  //    This is the direct fix for the PR 45.2 root cause: the
  //    anonymous launch session must NOT claim the token.
  if (isAnonymous) {
    logger?.breadcrumb?.('push: skip (anonymous user)');
    return { kind: 'skipped', reason: 'anonymous' };
  }
  // 3. Already registered for THIS uid → short-circuit (avoids
  //    permission-prompt spam + redundant callable invocations
  //    on every auth-state nudge for the same user).
  if (lastRegisteredUid === currentUid) {
    return { kind: 'skipped', reason: 'already_registered_this_uid' };
  }
  // 4. New real uid (incl. anonymous→real upgrade, or account
  //    switch) → register.
  try {
    const token = await registerForPush();
    if (token) {
      logger?.breadcrumb?.('bootstrap: push registered ok');
      return { kind: 'registered', token, uid: currentUid };
    }
    // null = permission denied / simulator / no projectId. Gate
    // stays open (caller does NOT update lastRegisteredUid) so a
    // later state change can retry.
    logger?.breadcrumb?.('bootstrap: push register skipped (null token)');
    return { kind: 'skipped', reason: 'null_token' };
  } catch (error) {
    logger?.captureException?.(error);
    return { kind: 'failed', error };
  }
}
```

Critical contract: the outcome includes `uid` on the
`registered` kind so the caller knows which uid to store as
`lastRegisteredUid`. The orchestrator itself stays pure (no
mutable state) — the caller owns the `lastRegisteredUid`
variable.

### B. AuthBootstrap — track lastRegisteredUid, pass uid + isAnonymous

`src/components/AuthBootstrap.tsx`. Replace the boolean
`pushRegisteredOk` with a `lastRegisteredUid` ref scoped INSIDE
the useEffect (resets on cold-start remount, persists across
auth events within a session — same scoping discipline as PR 45):

```ts
// Inside the useEffect, alongside the auth subscription:
let lastRegisteredUid: string | null = null;

// In the onAuthStateChanged callback, replacing the old
// `if (user && !pushRegisteredOk)` block:
runPushRegistration({
  currentUid: user?.uid ?? null,
  isAnonymous: user?.isAnonymous ?? false,
  lastRegisteredUid,
  registerForPush: () => pushService.registerForPushNotifications(),
  logger: {
    breadcrumb: msg => Sentry.addBreadcrumb({ category: 'push', message: msg }),
    captureException: err => Sentry.captureException(err, {
      tags: { push_stage: 'bootstrap_register' },
    }),
  },
})
  .then(outcome => {
    if (outcome?.kind === 'registered') {
      lastRegisteredUid = outcome.uid; // track WHO, not just "done"
    }
    // skipped/failed/null → leave lastRegisteredUid unchanged so
    // the next qualifying auth event retries.
  })
  .catch(() => {
    // Orchestrator never throws (defensive contract), but keep
    // the catch so a future regression can't bubble an unhandled
    // rejection in bootstrap.
  });
```

Keep the existing `PR 45.1 DIAGNOSTIC PROBE` breadcrumb at the
"reached push branch" point — but UPDATE its data payload to
include the decision-relevant fields so the next reproduce
clearly shows the fix working:

```ts
Sentry.captureMessage('bootstrap: reached push branch', 'info');
// breadcrumb data: { isAnonymous, currentUidPrefix, lastRegisteredUidPrefix }
```

(Truncate uids to a prefix — full uids aren't secret but the
prefix is enough to read the trail.)

### C. Tests — rewrite existing + add the regression cases

`tests/services/pushRegistrationOrchestrator.test.ts`. Rewrite
the 11 existing cases to the new `{ currentUid, isAnonymous,
lastRegisteredUid }` signature (behaviors preserved), then ADD:

1. **Anonymous user → skip** (THE root-cause regression test):
   `runPushRegistration({ currentUid: 'anon_1', isAnonymous: true,
   lastRegisteredUid: null, registerForPush })` →
   `{ kind: 'skipped', reason: 'anonymous' }`, `registerForPush`
   NOT called.
2. **Anonymous → real upgrade re-registers** (the exact bug):
   - First call: anonymous user → skipped, `registerForPush` not
     called, `lastRegisteredUid` stays null
   - Second call: same session, now `currentUid: 'real_admin'`,
     `isAnonymous: false`, `lastRegisteredUid: null` → registers,
     `registerForPush` called, outcome `{ kind: 'registered',
     uid: 'real_admin' }`
   - Assert the token ends up associated with the REAL uid, not
     the anonymous one.
3. **Account switch re-registers:**
   - Registered for `real_A` (lastRegisteredUid = 'real_A')
   - Auth event for `real_B` → registers again (different uid),
     `registerForPush` called
4. **Same real uid short-circuits:**
   - lastRegisteredUid = 'real_A', currentUid = 'real_A' →
     `{ kind: 'skipped', reason: 'already_registered_this_uid' }`,
     `registerForPush` NOT called
5. **No user → null:** `currentUid: null` → returns `null`,
   `registerForPush` not called
6. **Retry-on-failure preserved:** real uid, registerForPush
   throws → `{ kind: 'failed' }`, gate stays open (caller doesn't
   update lastRegisteredUid), next call with same uid retries
7. **Retry-on-null-token preserved:** real uid, registerForPush
   resolves null → `{ kind: 'skipped', reason: 'null_token' }`,
   gate stays open

Target ~14 cases total (the rewritten existing + the new
anonymous/uid-change ones). The whole point: case 1 + case 2 are
the regression tests that would have caught this bug before it
ever shipped.

## Discipline checklist

- [ ] `lastRegisteredUid` scoped INSIDE the useEffect (resets on
      remount), NOT module-level. Same trap as PR 45's
      `pushRegisteredOk`.
- [ ] Orchestrator stays pure — no mutable module state. The
      caller owns `lastRegisteredUid`; the orchestrator just
      reads it as input and returns the new uid on success.
- [ ] Anonymous check uses Firebase's `user.isAnonymous` (RNFB
      auth user property), not a custom heuristic.
- [ ] PR 45.1 diagnostic probes left in place (stripped in a
      later cleanup OTA after device verification).
- [ ] No schema changes, no functions changes, no native
      rebuild. Pure client OTA.
- [ ] All existing orchestrator tests rewritten (not deleted) so
      coverage doesn't regress.
