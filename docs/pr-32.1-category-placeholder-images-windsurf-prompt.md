# PR 32.1 — Category-aware placeholder images (Windsurf prompt)

## Why this PR exists

PR 32's `addExtractedMenuItems` callable and PR 6's
`addCustomMenuItem` callable both fall back to a single generic
placeholder when no `imageUrl` is supplied:

```ts
const fallbackImage =
  'https://placehold.co/400x400/e2e8f0/64748b?text=Custom+Item';
```

So a shopkeeper who scans a 60-SKU rate-list (PR 32 happy path)
ends up with 60 menu items all showing the same gray "Custom
Item" box. **Looks low-effort, which directly conflicts with
Trust Principle 2** (the review-before-commit UX is supposed
to make the AI-extracted menu feel polished). A customer
browsing that shop's menu sees identical placeholder squares
across 10 different food categories — looks unprofessional,
makes the shop look new and untrusted.

**PR 32.1 replaces the single placeholder with 10
category-themed placeholders** (one per `CategoryId`), all
generated via `placehold.co` with category-appropriate emoji
+ color. Zero new asset uploads, zero new infrastructure.

- atta_rice_dal → wheat-themed cream/brown
- oil_ghee → oil-bottle-themed yellow
- dairy_eggs → milk-themed white/blue
- bakery → bread-themed beige
- masala_spices → spice-themed red/orange
- snacks_biscuits → snack-themed light brown
- beverages → beverage-themed pink/red
- personal_care → toiletry-themed pale blue
- household → cleaning-themed neutral green
- fruits_vegetables → fresh-produce-themed green

A scanned 60-SKU menu now shows visually differentiated rows
that look categorized rather than identically empty. Customer
sees "okay, this shop has lots of stuff and it's organized."

**~2 hrs Windsurf work. OTA + functions deploy. No rules
changes, no new SDKs, no secrets, no native rebuild.**

## Critical lessons from PRs 25–36.1 (do not repeat)

1. **OTA-eligible** + server deploys. No native build.
   Confirm via `git diff main -- app.json package.json` is empty.
2. **Verify field names against source first** (the PR 36
   lesson). Specifically: confirm what the per-item write
   looks like in both `addExtractedMenuItems` and
   `addCustomMenuItem` — different code paths, both need
   updating, both need the same fallback selection logic.
3. **One source of truth.** The category-to-URL map lives in
   exactly ONE place (the new `CATEGORY_PLACEHOLDER_URLS`
   constant in `functions/src/categoryConstants.ts`). Both
   callables import from it. Don't duplicate.
4. **Schema-additive only.** PR 32.1 changes the *value*
   written to `imageUrl` on new items but not the *field
   shape*. Existing menu items keep their URLs; only items
   added AFTER deploy use the new placeholders.
5. **No `DO NOT REMOVE` markers expected.** No new long-lived
   imports at risk.
6. **Server-first deploy.** Two callables redeploy; client
   needs no changes (reads `imageUrl` regardless of value).
   Technically the OTA isn't even needed for PR 32.1 to take
   effect — function redeploy alone activates new fallback
   behavior. But push an OTA anyway so any tests / client-side
   PRELAUNCH update lands.

## Scope (in)

### Part 1 — Add `CATEGORY_PLACEHOLDER_URLS` to `categoryConstants.ts`

In `functions/src/categoryConstants.ts`, alongside the existing
`VALID_CATEGORIES` set, add:

```ts
import { type DocKind } from './kycUploadHelpers'; // remove this line if not actually needed; pattern check only

// PR 32.1 — category-themed placeholder image URLs. Used by
// addExtractedMenuItems (PR 32) and addCustomMenuItem (PR 6
// era) when the shop owner adds an item without supplying
// an imageUrl. Single source of truth — both callables import
// from here. URLs are placehold.co with category emoji + a
// theme color so the menu looks intentionally categorized
// instead of uniformly placeholder-gray.
//
// Format note: placehold.co accepts `?text=...` with URL-
// encoded characters; emoji works (UTF-8 percent-encoded).
// Color tuples are `bgHex/textHex` in the URL path.
//
// If placehold.co goes down or rate-limits, the placeholder
// images break gracefully — the MenuItem.imageUrl field still
// has a URL, the client's <Image> falls back to its own
// `defaultSource` / "image failed to load" handling. Worst
// case: customer sees a blank rectangle instead of a themed
// one. No crash, no data loss.
export const CATEGORY_PLACEHOLDER_URLS: Record<string, string> = {
  // wheat/grain — cream bg, brown text
  atta_rice_dal:
    'https://placehold.co/400x400/F5E6D3/8B4513?text=%F0%9F%8C%BE+Atta+%26+Rice',
  // oil bottle — yellow bg, brown text
  oil_ghee:
    'https://placehold.co/400x400/FFF3B0/8B4513?text=%F0%9F%AB%92+Oil+%26+Ghee',
  // dairy carton — pale blue bg, dark blue text
  dairy_eggs:
    'https://placehold.co/400x400/E3F2FD/1A237E?text=%F0%9F%A5%9B+Dairy+%26+Eggs',
  // bread — beige bg, brown text
  bakery:
    'https://placehold.co/400x400/F5DEB3/8B4513?text=%F0%9F%8D%9E+Bakery',
  // spices — light red bg, dark red text
  masala_spices:
    'https://placehold.co/400x400/FFCCBC/BF360C?text=%F0%9F%8C%B6+Masala',
  // snacks — light brown bg, dark brown text
  snacks_biscuits:
    'https://placehold.co/400x400/D7CCC8/4E342E?text=%F0%9F%8D%AA+Snacks',
  // beverages — pink bg, dark red text
  beverages:
    'https://placehold.co/400x400/FFE0B2/E64A19?text=%F0%9F%A5%A4+Beverages',
  // personal care — pale lavender bg, deep purple text
  personal_care:
    'https://placehold.co/400x400/E1BEE7/4A148C?text=%F0%9F%A7%B4+Personal+Care',
  // household — pale green bg, dark green text
  household:
    'https://placehold.co/400x400/C8E6C9/1B5E20?text=%F0%9F%A7%BD+Household',
  // fresh produce — bright green bg, dark green text
  fruits_vegetables:
    'https://placehold.co/400x400/AED581/1B5E20?text=%F0%9F%A5%95+Fruits+%26+Veg',
};

/**
 * PR 32.1 — return the category-themed placeholder URL.
 * Falls back to the original generic placeholder for any
 * categoryId not in the map (defense against future schema
 * drift where a new CategoryId is added but the map isn't
 * updated). Pure function, exported so both callables import
 * the same lookup.
 */
export function placeholderImageForCategory(
  categoryId: string,
): string {
  return (
    CATEGORY_PLACEHOLDER_URLS[categoryId] ??
    // Legacy fallback identical to the pre-PR-32.1 generic.
    'https://placehold.co/400x400/e2e8f0/64748b?text=Custom+Item'
  );
}
```

Remove the line `import { type DocKind } from './kycUploadHelpers';`
if no other code in the file needs it — it was added illustratively
and may not actually belong there.

**Important consistency check:** the 10 keys in
`CATEGORY_PLACEHOLDER_URLS` MUST exactly match the 10 entries in
`VALID_CATEGORIES`. The test suite enforces this (Part 4 below).
If a future PR adds a new `CategoryId`, the map needs the new
entry too — the `VALID_CATEGORIES`-vs-`CATEGORY_PLACEHOLDER_URLS`
parity test catches it.

### Part 2 — Use the per-category placeholder in `addExtractedMenuItems`

In `functions/src/index.ts`, find the `addExtractedMenuItems`
callable (the one PR 32 added). Inside the per-item loop, replace
the line that writes the imageUrl with:

```ts
// Before (PR 32):
// const fallbackImage = 'https://placehold.co/400x400/e2e8f0/64748b?text=Custom+Item';
// batch.set(..., { ...item, imageUrl: fallbackImage, ... });

// After (PR 32.1):
import { placeholderImageForCategory } from './categoryConstants';
// (add to existing import line if categoryConstants is already imported)

// Inside the loop:
batch.set(db.doc(`shops/${shopId}/menu/${menuItemId}`), {
  ...
  imageUrl: placeholderImageForCategory(item.category),
  ...
});
```

The category is already validated against `VALID_CATEGORIES`
earlier in the same callable (PR 32's validator), so by the
time we reach the write line, `item.category` is guaranteed
to be one of the 10 known IDs and the lookup always hits.

### Part 3 — Use the per-category placeholder in `addCustomMenuItem`

In `functions/src/index.ts`, find `addCustomMenuItem` (around
line 4498, PR 6 era). Same pattern:

```ts
// Before:
// const fallbackImage = 'https://placehold.co/400x400/e2e8f0/64748b?text=Custom+Item';
// const finalImageUrl = imageValidation.url ?? fallbackImage;

// After:
const finalImageUrl =
  imageValidation.url ?? placeholderImageForCategory(category);
```

The `category` field on `addCustomMenuItem`'s input is already
validated against `VALID_CATEGORIES` earlier in the same
callable, so the lookup always hits.

**Don't change** the validation logic, the storagePath helpers,
or anything else — just the fallback selection.

### Part 4 — Tests

Create `tests/functions/categoryPlaceholders.test.ts`:

```ts
import {
  CATEGORY_PLACEHOLDER_URLS,
  placeholderImageForCategory,
} from '../../functions/src/categoryConstants';
import { VALID_CATEGORIES } from '../../functions/src/categoryConstants';

describe('PR 32.1 — category placeholders', () => {
  test('CATEGORY_PLACEHOLDER_URLS has an entry for every VALID_CATEGORIES id', () => {
    for (const id of VALID_CATEGORIES) {
      expect(CATEGORY_PLACEHOLDER_URLS[id]).toBeDefined();
      expect(CATEGORY_PLACEHOLDER_URLS[id]).toMatch(/^https:\/\/placehold\.co\//);
    }
  });

  test('CATEGORY_PLACEHOLDER_URLS has no extra ids beyond VALID_CATEGORIES', () => {
    const validSet = new Set(VALID_CATEGORIES);
    for (const id of Object.keys(CATEGORY_PLACEHOLDER_URLS)) {
      expect(validSet.has(id)).toBe(true);
    }
  });

  test('every URL is a syntactically valid URL', () => {
    for (const url of Object.values(CATEGORY_PLACEHOLDER_URLS)) {
      expect(() => new URL(url)).not.toThrow();
      expect(url).toMatch(/^https:\/\//);
    }
  });

  test('placeholderImageForCategory returns the right URL for each id', () => {
    for (const id of VALID_CATEGORIES) {
      expect(placeholderImageForCategory(id)).toBe(
        CATEGORY_PLACEHOLDER_URLS[id],
      );
    }
  });

  test('placeholderImageForCategory falls back to the generic placeholder for unknown ids', () => {
    expect(placeholderImageForCategory('not_a_real_category')).toMatch(
      /text=Custom\+Item/,
    );
  });

  test('placeholderImageForCategory falls back to the generic placeholder for empty string', () => {
    expect(placeholderImageForCategory('')).toMatch(/text=Custom\+Item/);
  });
});
```

6 tests, all pure, no mocking required.

## Scope (out)

- **Updating existing menu items** to use the new placeholders.
  Items added before this PR keep their existing imageUrl
  (whether it's the old generic placeholder, an uploaded image,
  or a seed image). Only items added AFTER deploy use the new
  fallbacks. Migrating existing items is a separate workstream
  if/when the pilot shows a visible-consistency problem.
- **Real product images via Open Food Facts lookup.** Deferred to
  PR 32.2 (post-pilot) per the conversation that produced this
  PR 32.1. The OFF integration would do a background lookup
  for each scanned item and swap the placeholder for a real
  product image if matched.
- **Master product catalog matching** (PR 33 territory). The
  proper long-term fix — match scanned items against a curated
  master catalog and use the master's image when matched.
  Currently deferred per the pilot-trim decisions in ROADMAP.md.
- **Client-side caching of the placeholder images.** placehold.co
  serves with reasonable cache headers; the React Native
  `<Image>` component honors those. Don't over-engineer caching
  in v1.
- **Localized placeholder text** (e.g., Hindi labels on each
  placeholder). Out of scope for v1; the emoji + English is
  enough signal for the pilot.

## Why this PR matters

For a small fix, this has disproportionate impact on **how a
new shop's menu looks at the moment it's most likely to be
seen** — during the customer's first browse of a recently
onboarded shop. Pilot success depends partly on customers
trusting that the shop is real, organized, and worth ordering
from. A grid of 30 identical gray placeholders signals "this
shop hasn't set up properly yet" — even if the item *names*
and *prices* are all there.

PR 32.1 makes the same 30-item menu look intentional and
categorized at first glance, with zero new asset work and
zero deploy complexity. It's the kind of tiny detail that
makes the difference between "looks like a beta" and "looks
like a real shop."

This is also one of the smaller PRs in the project — a single
constant file + two surgical callable edits + a small test
suite. The cross-check pattern catches anything that goes
wrong (parity test ensures the placeholder map and the
category set stay in sync forever). And once PR 33 (master
product catalog) eventually un-defers, the placeholder layer
gracefully yields to real product images for matched SKUs
— PR 32.1 is the bridge, not the dead-end.
